# JScratch guidance

Read [README.md](README.md) before changing this engine or writing game programs. Before editor work, also read [editor/README.md](editor/README.md) for the editor architecture, persistence, UI constraints and verification workflow.

JScratch is a JavaScript API inspired by Scratch blocks. `program/begin.js` defines startup/menu flow and `program/world.js` defines the playable World scene; `js/` implements the reusable engine. Preserve this separation. Do not rewrite the user's game or add scenes unless requested.

Keep the folder name and URL capitalization exactly `JScratch`. Shared website tools live in `../webpages/apps/`; the shared skill stylesheet lives in `../assets/css/mlg-skill.css`.

Camera defaults live in `camera.json`; executable camera blocks live in `js/camera.js`. Camera following is opt-in; preserve the default `(0, 0)` view unless the game or config explicitly requests otherwise.

UI objects in `js/ui.js` are procedural Sprite subclasses and default to world coordinates. `spriteCoordinateMode(name, "canvas")` is opt-in for any sprite: logical-stage-unit edge-to-center distances from selected canvas sides, default left/top, independent of camera/zoom. Keep `program/sample.js` in the user's flat section-and-inline-comment style; do not wrap the reference in a catalog object or category functions.

`coordinatePlane(name, horizontal, vertical)` selects canvas mode with left/right and top/bottom inward logical-stage-unit distances from canvas sides to the sprite center. Preserve those offsets on resize; x/y remain distances in the selected plane. `moveToEdge` was removed; use coordinatePlane then moveTo.

Startup commands belong inside `whenStart(...)`; startup hats run concurrently on each restart. `editor/index.html` and `editor/` provide the visual editor through the existing Wrangler server. Do not add a separate editor server. Browser folder access handles direct program-file autosave. New public blocks must follow [BLOCKS.md](BLOCKS.md) and use `defineJScratchBlock` in `js/extensions.js`. Metadata drives both runtime constructors and the editor; do not duplicate signatures or edit vendor code. Run `node JScratch/editor/build-catalog.mjs` after legacy block or externally created program-file changes. Keep import syntax-only; never execute imported game code in the editor.

Programs load recursively from `program/project.json`. All files register before startup; use event hats and explicit synchronization rather than relying on file/folder order. The editor automatically includes newly saved files and subfolders and excludes sample.js/reference examples from execution. Preserve bold filled blocks with white labels, white fields with black text, subtle darker outlines in each block’s own color, and renderer-based body label alignment. The editor is canvas-first: no full-width header/footer bars, collapsible file and palette/search panels, and compact floating controls. Save game source in program/ and editor metadata in editor/ using remembered permission for their JScratch parent folder; do not add a persistent folder-change button or claim browsers can silently write without permission.

Keep block arguments inline, including UI and glide blocks, with automatic continuation rows at the 800-unit target in editor/renderer.mjs. Restore older saved blocks to inline inputs when loading; let the renderer wrap whole arguments without changing their names, order, or source code. Statement bodies still nest on their own rows.

Palette preview scale is independent of canvas zoom. Preserve the getFlyoutScale override in editor/palette.mjs and Blockly’s native drag conversion; do not resize palette blocks when fitting or zooming the workspace.

Compact editor wording belongs in editor/labels.mjs (var, val/val2, width/height/radius, etc.). Change display labels only; never rename public JavaScript functions, parameter keys, or user-authored strings to match visual abbreviations.

Keep the workspace full-window when the palette opens; palette.mjs positions its flyout below floating controls without creating an empty strip above the canvas.

Run opens editor/player.html (hosting canvas.html) and editor/inspector.html in separate windows linked by a random inspection session. Preserve the read-only snapshot boundary: never evaluate reporters/getters while inspecting, expose variable previews rather than engine/image objects, and include original sprites, UI and clones. Inspector selection IDs include runId. Keep list rendering virtualized and snapshots request-driven; ordinary game visits must not collect them. Do not add inspector mutation controls without a user request.

Smart field roles live in editor/symbols.mjs and are rendered by editor/smart-fields.mjs; preserve raw JS VALUE serialization and reporter connections. Names are indexed across executable files and saved in editor/editor-data.json plus browser drafts. Never permit deletion of referenced names; keep costume paths and sprite vars scoped to their owner/clone family. Color pickers must support opacity; numbers stay directly editable, and Expression… preserves computed arguments. Disable the yellow selection overlay rather than hiding drag-insertion feedback.

Project name references and renames live in editor/references.mjs. Parse only, edit exact source offsets, preserve unrelated text, respect private owner scopes, and preview multi-file changes. Keep dynamic/raw-code warnings and disk baseline checks; never execute imported source to find references. Sprite/custom-block renames migrate saved private buckets.

User custom blocks use defineFunction(name, parameters, ...body), callFunction(name, ...values), functionValue, setFunctionValue, returnFunction and functionResult. Definitions are top-level declarations collected before startup. Calls and returns use explicit scheduler frames (never recursive JS execution), preserve clone context, isolate each call's locals, and cannot break the caller's loops. Metadata variadic command arguments are stored under reserved _args. Keep custom palette calls parameter-labeled and preserve extra connected arguments on signature changes.

Run-at-broadcast resets and runs finite startup with all broadcasts suppressed, then releases normal broadcast behavior and launches all matching entry listeners concurrently. Do not replay arbitrary skipped scene listeners or change normal startup. The preview entry is a local URL option, not a source rewrite. Stop/error during setup must prevent entry launch; a restart block encountered during suppressed initialization is skipped to prevent reboot loops.

Draggable definition-header parameter pills live in editor/parameters.mjs. They derive from the literal parameter list, clone into compact js_parameter reporters, and serialize back to functionValue(name); do not add a second runtime variable system. Keep ownership checks, nested-body use, source compatibility and saved-layout migration. The header must remain intact while dragging. Use Blockly's native dragger for snapping/zoom/touch and group creation plus insertion for undo. Primitive field defaults use shadows only in rendered workspaces (Blockly shadow serialization needs DOM); preserve computed expression blocks. Derived header controls are not executable inputs or serializable fields.

Keep user block coordinates stable. editor/layout.mjs preserves per-file anchors and canvas view through refresh, file switches, source rebuilding, parameter changes and renames; new roots go beside existing ones. Arrange automatically only on a file's first visit when no remembered layout exists. Expanding/migrating old layouts must never arrange or recenter them. Browser layouts are separate from source drafts and flush on hide/unload; editor/editor-layouts.json backs up positions/view through existing folder permission. Do not put editor metadata into executable program manifests. Preserve exact negative/fractional coordinates, and reserve unchanged-script matches before assigning positions to new roots.

The editor is optional and self-contained under editor/ (index.html, player.html, inspector.html, bridge/model modules, vendor libraries and metadata JSON). canvas.html and js/ must never import or fetch editor assets. Editor Run hosts canvas.html in an editor-owned preview iframe and attaches the read-only inspector there. Raw program JS plus program/project.json must run with editor/ physically absent. Use projectPaths(import.meta.url) for editor-to-runtime URLs, retain browser-storage migration, and request the JScratch parent folder for program/ plus editor/ autosave; legacy program-only grants retain source writes without placing metadata in program/.

Boolean/value editor roles and saved-state migration live in editor/types.mjs. Boolean reporters/sockets are hexagonal and rounded Value outputs cannot enter Boolean-only inputs; general value inputs may accept Boolean results. Migrate saved workspaces before connecting stricter types, preserving old source semantics and all script anchors. Keep infix symbols/readable labels in editor/labels.mjs; runtime function names and parameter ordering remain unchanged. New metadata supports reporter output:"boolean" and parameter type:"boolean" (or picker:"boolean"). See editor/README.md for compatibility-wrapper and test-reporter generation rules.

Empty-field rules live in editor/field-values.mjs: infer text/name/path roles centrally, display empty strings as blank, and serialize clearing as "" for text or 0 for numeric/value fields. Preserve real metadata defaults, existing authored values, Boolean choices and structured inputs. Do not reintroduce synthetic Sprite/Play/Text placeholders or quotes/(none) in empty fields. Palette defaults and plain/smart field validation must agree, without changing raw VALUE serialization or pausing autosave on a cleared field.

Canvas defaults to a declared 540x360 logical box. canvasSize sets it at execution/startup; canvasWidth/canvasHeight report it unchanged by browser resizing. Fit scale is containerHeight/declaredHeight, with no letterboxing; the centered visible width responds to screen aspect ratio and narrow phones crop the sides. Keep declared box width separate from baseViewWidth (visible stage-unit span). screenWidth/screenHeight report the visible span before camera zoom. Sprite modes are world (camera-transformed centers), canvas (full-box edge gaps), and screen (visible-viewport edge gaps); screen is no longer an alias. Both fixed modes scale size/gaps with height and ignore camera pan/zoom. coordinatePlane preserves existing screen mode. Preserve shared forward/inverse geometry, hit/solid/culling alignment, cloning, DPI/ResizeObserver and page-relative camera config.

Keep logical stage dimensions separate from raster resolution. Backing canvas dimensions are actual display CSS width/height times devicePixelRatio; baseUnitScale is displayScale*pixelRatio. Canvas/screen rendering and forward/inverse/solid geometry use baseUnitScale (not raw pixelRatio), while world rendering uses unitScale including camera zoom. Never reintroduce a stage-sized intermediate that loses source image detail before CSS enlargement. Preserve original-resolution costume/GIF/effect caches and nearest-neighbor crispness.

Screen-mode anchor bounds are the intersection of the visible viewport and declared canvas box: min(baseViewWidth, ENGINE.width), centered horizontally. Portrait HUDs follow visible sides, but widescreen HUDs cannot anchor beyond the declared box. Apply through spriteCanvasArea for both forward/inverse geometry; do not independently clamp drawing positions or change world motion. screenWidth still reports the actual visible span, not the capped anchor width.

All sprite coordinates/targets/distances, including canvas/screen edge offsets, refer to the sprite center. Do not add/subtract half-extents in spriteCanvasPosition or its inverse: size/rotation must leave the center unchanged so images and UI grow equally in every direction. Keep screen anchoring bounded by the viewport/declared-box intersection; exact-fit screens share canvas-mode distances. Rectangular/alpha extents remain relevant to rendering/collision/culling, not the position origin.

Rendering clips to stageVisibleArea(), shared with screen anchors: do not let oversized world backgrounds paint beyond the declared box and create a false visual edge. Camera drawable viewWidth is min(baseViewWidth, declared width)/zoom; screenWidth still includes logical side-bar span. Pointer hits outside the shared visible box are excluded. Preserve center-based offsets in logical units (50 becomes 100 display pixels at scale 2), never raw browser-pixel offsets or half-extent compensation.
